## 插件是什么

一个插件就是插件文件夹里的一个文件夹，里面有：

- `plugin.json`：说明它叫什么、怎样启动。
- 程序本身：一个脚本（`.py`、`.js`、`.ps1`、`.bat`）或一个 `.exe`，用什么语言写都可以。

FullWidget 把它当成一个独立的程序运行（看不到窗口），用**标准输入和标准输出**和它通信，一行一个 JSON：

```
组件  ──widget.plugin("obs").call("status")──▶  FullWidget  ──{"id":1,"method":"status"}──▶  插件
组件  ◀──────────── 结果 ─────────────────────  FullWidget  ◀──{"id":1,"result":{...}}──────  插件
组件  ◀──────── .on("changed", …) ────────────  FullWidget  ◀──{"event":"changed",...}──────  插件（随时）
```

**什么时候需要插件：**

| 想做的事 | 用什么 |
|---|---|
| 从网上拿数据 | 不用插件：组件里的 `widget.fetch`（`network:` 权限） |
| 偶尔跑一条命令、看它的输出 | 不用插件：组件里的 `widget.shell.run` 或 `widget.shell.exec`（`shell.run` 权限，见[组件开发指南](组件开发指南.md)） |
| 要一直开着、记住状态、持续送数据（连着 OBS、监听硬件、每秒读传感器） | 插件 |
| 要用某种语言的库（Python 的 `psutil`、Node 的某个 SDK） | 插件 |
| 一条命令很慢、每次启动都要好几秒 | 插件：启动一次，之后每次调用都很快 |

**限制：** 只有你自己写的组件能用你的插件。用“新建组件”创建的组件可以直接用；自己复制进组件目录的，第一次要在控制中心“我的组件”里允许它的权限。用了插件的组件不能打包成安装包（.fwz），也不会上组件市场。

## 五分钟试一个

1. 控制中心 →“设置”→“插件”→“新建插件”，名称填 `hello`。FullWidget 会创建一个能运行的 PowerShell 插件、打开它的文件夹，并且直接允许它。
2. 控制中心 →“添加组件”→“新建组件”，创建一个组件。
3. 在组件的 `widget.json` 的 `permissions` 加上 `"plugin:hello"`：

```json
"permissions": ["plugin:hello"]
```

4. 在组件的 `main.js` 里：

```js
const hello = widget.plugin("hello");
document.body.textContent = await hello.call("hello", { name: "小明" });
hello.on("tick", (d) => console.log("插件说现在是", d.time));
```

组件上会出现“你好，小明！现在是 …”。示例插件的 `main.ps1` 有注释，可以从它改起。

## 文件夹和 plugin.json

插件文件夹在数据位置里的 `plugins`，一般是 `%AppData%\FullWidget\plugins`（控制中心“设置 → 插件 → 打开文件夹”可以直接打开）：

```
plugins\
  obs\                 文件夹名称就是插件名称
    plugin.json
    main.py
    requirements.txt   （随你：插件自己需要的其他文件）
```

**插件名称**（文件夹名称）：英文字母、数字、`.`、`_`、`-`，以字母或数字开头，最长 64 个字符，不分大小写。`fullwidget.` 开头的名称留给[官方插件](#官方插件)。

**plugin.json：**

```json
{
  "name": "OBS",
  "description": "读取 OBS 的直播和录像状态，也可以开始和停止。",
  "run": "main.py",
  "idleMinutes": 5
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `run` | 是 | 怎样启动它。见下面 |
| `name` | 否 | 显示在控制中心的名称，默认是文件夹名称。可以写成 `{"zh-TW": "…", "zh-CN": "…", "en": "…"}` |
| `description` | 否 | 一句话说明它做什么，显示在控制中心。也可以分语言 |
| `idleMinutes` | 否 | 没有组件在用多少分钟后让它停下，默认 `5`；`0` 表示一直开着，直到 FullWidget 结束。最大 1440 |
| `version` | 否 | 版本号，例如 `"1.0.0"`，显示在控制中心 |

文件用 UTF-8 存，可以有 BOM、`//` 注释和结尾多余的逗号。

**`run` 怎么写：** 在插件文件夹里运行。

| 写法 | 实际运行 |
|---|---|
| `"main.py"` | `python main.py`（要装好 Python，`python` 在 PATH 里） |
| `"main.js"` 或 `"main.mjs"` | `node main.js`（要装好 Node.js） |
| `"main.ps1"` | `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File main.ps1`（Windows 自带的 PowerShell 5.1） |
| `"main.bat"` 或 `"main.cmd"` | `cmd.exe /d /s /c main.bat` |
| `"bin\\tool.exe --port 4455"` | 直接运行这个程序，后面是参数 |
| `"python -u main.py --verbose"` | 直接写完整的命令也可以 |
| `"\"C:\\Program Files\\My Tool\\tool.exe\" --serve"` | 有空格的路径用引号包起来 |
| `"pwsh -NoProfile -File main.ps1"` | 用 PowerShell 7 |
| `".venv\\Scripts\\python.exe main.py"` | 用插件文件夹里的 Python 虚拟环境 |

**改了 plugin.json 要再允许一次。** FullWidget 记住的是 plugin.json 的内容，内容一变（多一个空格也算），插件就变回“等你允许”。改程序本身不用。

## 通信协议

所有消息都是**一行一个 JSON 对象**，UTF-8 编码，以换行结束。JSON 里不能有换行（字符串里的换行要写成 `\n`，一般的 JSON 函数库默认就是这样）。

### FullWidget 送给插件（标准输入）

```json
{"id": 1, "method": "hello", "params": {"name": "小明"}, "widget": "user.my-widget", "instance": "a1b2c3"}
```

| 字段 | 说明 |
|---|---|
| `id` | 整数，这次请求的编号。回答时原样带回 |
| `method` | 字符串，组件 `call` 的第一个参数 |
| `params` | 组件 `call` 的第二个参数，任何 JSON 值；没传时是 `null` |
| `widget` | 调用它的组件的 id（`widget.json` 的 `id`） |
| `instance` | 桌面上是哪一个（同一个组件放了两个时不同） |

### 插件回答（标准输出）

成功：

```json
{"id": 1, "result": "你好，小明"}
```

`result` 可以是任何 JSON 值（字符串、数字、对象、数组、`null`）。组件的 `await plugin.call(...)` 拿到的就是它。

失败：

```json
{"id": 1, "error": "找不到 OBS，请确认 OBS 已经打开"}
```

`error` 写一句给人看的话，组件那边的 promise 会失败，`e.message` 就是这句话。也可以写 `{"message": "…"}` 对象。

- 每个请求都要回答一次，而且只回答一次。没回答的话，组件等到超时（默认 30 秒）会收到失败。
- 可以不照顺序回答：FullWidget 可能在你回答前就送来下一个请求。慢的工作放到另一个线程或异步做，先处理后面的请求也可以。
- 回答了不存在的 `id`（例如已经超时的），FullWidget 会忽略。

### 插件主动送事件（标准输出）

```json
{"event": "changed", "data": {"streaming": true, "seconds": 125}}
```

任何时候都可以送，不用等请求。所有正在 `.on()` 听这个插件的组件都会收到；没有组件在听时，事件直接丢掉。`event` 是字符串，`data` 是任何 JSON 值。

### 规则

- **标准输出只能写上面这三种 JSON 行。** 任何其他输出（`print("debug")`、进度条、库打印的警告）都会让 FullWidget 在日志里警告，并被忽略。给自己看的消息写到**标准错误**（stderr），会记进 `app.log`，前面标着 `[plugin 名称]`。
- **每写一行都要 flush**，不然数据留在缓冲区，FullWidget 收不到：
  - Python：`print(..., flush=True)`（FullWidget 已经设好 `PYTHONUNBUFFERED=1`）。
  - Node.js：`process.stdout.write(json + "\n")` 会直接送出。
  - C#：`Console.Out.Flush()`，或开头设 `Console.Out` 为 `AutoFlush`。
  - PowerShell：`[Console]::Out.WriteLine(...)` 后 `[Console]::Out.Flush()`。
- **编码一律 UTF-8**，没有 BOM。FullWidget 为 Python 设好了 `PYTHONUTF8=1` 和 `PYTHONIOENCODING=utf-8`。C# 和 PowerShell 要自己设输出编码（见示例）。
- 多个线程都会写标准输出时，要加锁，一次写完整的一行，不然两行会混在一起。
- **标准输入被关掉**（读到文件结尾）表示 FullWidget 要你结束：收尾，然后退出。3 秒内没退出会被强制结束。

### 环境变量

| 变量 | 内容 |
|---|---|
| `FULLWIDGET_PLUGIN` | 插件名称 |
| `FULLWIDGET_VERSION` | FullWidget 的版本，例如 `1.4.0` |
| `FULLWIDGET_LANG` | 界面语言：`zh-TW`、`zh-CN` 或 `en`，回错误消息时可以用 |

工作目录是插件文件夹，读写自己的配置文件用相对路径就可以。

## 什么时候运行

- **第一次用到时启动。** 组件第一次 `call` 或 `on` 这个插件时，FullWidget 才启动它。之后所有组件共用同一个程序。
- **没人用就停下。** 没有组件在 `on` 听它、也没有请求在等，`idleMinutes` 分钟后 FullWidget 关掉它的标准输入，让它结束。下次用到再启动。要一直开着，写 `"idleMinutes": 0`。
- **自己结束了会重开。** 插件自己退出（出错、崩溃）时，如果还有组件在听它的事件，FullWidget 会等 1、5、15、30 秒后再启动它。正在等回答的请求会马上失败。
- **一直崩溃就停下。** 3 分钟内停了 5 次，FullWidget 不再重开，控制中心显示“一直停下来，已经停止”和最后的错误。修好后在“设置 → 插件”按“重新启动”。
- **存盘就重开。** 插件文件夹里的文件改了，运行中的插件会自动重新启动，改程序不用自己重开。
- **跟着 FullWidget 结束。** FullWidget 结束时，插件和插件启动的所有程序都会一起结束，不会留在后台。

所以插件启动时要快、不要等用户输入，有状态要自己存到文件里（重开后读回来）。

## 在组件里使用

**1. 声明权限。** 在组件的 `widget.json`：

```json
"permissions": ["plugin:obs"]
```

用几个插件就写几个 `plugin:名称`。

**2. 调用方法：**

```js
const obs = widget.plugin("obs");

try {
  const s = await obs.call("status");                       // 等插件回 result
  render(s);
} catch (e) {
  show(e.message);                                          // 插件回的 error，或插件不能用的原因
}

await obs.call("start", { scene: "Live" });                 // 第二个参数就是插件收到的 params
await obs.call("export", null, { timeout: 120_000 });       // 慢的工作：等最多 120 秒（默认 30 秒，最长 10 分钟）
```

**3. 听事件：**

```js
const off = obs.on("changed", (data) => render(data));     // 插件送 {"event":"changed","data":…}
obs.on("*", (data, event) => console.log(event, data));    // "*" 收全部事件
off();                                                      // 不再听
```

- `on` 会让插件启动（如果还没运行），并让它在你听的期间一直开着。
- 组件关掉或重新加载时，FullWidget 会自动停止它的监听，不用自己 `off()`。
- 插件重新启动之后，事件会自动继续送来，不用重新 `on`。但插件重开后的状态要靠你自己再拿一次：常见做法是插件启动时先送一次完整状态的事件，或组件定时 `call` 一次。

**4. 处理插件不能用的情况。** `call` 失败的原因可能是插件还没允许、还没装、一直崩溃。把 `e.message` 显示在组件上，用户就知道要去哪里处理。常见消息见[常见错误](#常见错误)。

TypeScript 类型在 `sdk/widget.d.ts`：

```ts
interface Plugin {
  readonly name: string;
  call<T = any>(method: string, params?: any, options?: { timeout?: number }): Promise<T>;
  on(event: string, listener: (data: any, event: string) => void): () => void;
}
```

## 完整示例

下面四个插件做的事完全一样，选你熟悉的语言：

- 方法 `hello`：参数 `{"name": "小明"}`，回 `"你好，小明"`。
- 方法 `add`：参数 `{"a": 1, "b": 2}`，回 `3`。
- 方法 `slow`：等 3 秒再回 `"done"`，示范慢的工作不会卡住其他请求。
- 其他方法回错误。
- 每 5 秒送一次事件 `tick`：`{"time": "14:03:05"}`。

每个示例都可以直接存盘使用，和这个组件搭配：

**组件 `widget.json`**（`permissions` 这一行是重点）：

```json
{
  "id": "user.plugin-demo",
  "name": "插件示范",
  "version": "1.0.0",
  "entry": "index.html",
  "size": { "width": 260, "height": 140 },
  "permissions": ["plugin:demo"]
}
```

**组件 `index.html`**（`widget` 对象和基本样式由 FullWidget 自动加上，不用引入）：

```html
<!doctype html>
<html>
<head>
  <meta charset="utf-8">
</head>
<body>
  <div id="hello" class="w-title">…</div>
  <div id="tick" class="w-label">等插件的第一个 tick</div>
  <script src="main.js"></script>
</body>
</html>
```

**组件 `main.js`：**

```js
const demo = widget.plugin("demo");
const $ = (id) => document.getElementById(id);

try {
  $("hello").textContent = await demo.call("hello", { name: "小明" });
  console.log("1 + 2 =", await demo.call("add", { a: 1, b: 2 }));
} catch (e) {
  $("hello").textContent = "插件不能用：" + e.message;
}

demo.on("tick", (d) => { $("tick").textContent = "插件时间 " + d.time; });
```

### Python

文件夹 `plugins\demo\`。要先装 [Python 3](https://www.python.org/downloads/)（安装时勾选“Add python.exe to PATH”）。

`plugin.json`：

```json
{ "name": "示范（Python）", "run": "main.py" }
```

`main.py`：

```python
import json, sys, threading, time

lock = threading.Lock()

def send(obj):
    """写一行 JSON 到 stdout。多个线程都会写，所以加锁。"""
    line = json.dumps(obj, ensure_ascii=False)
    with lock:
        sys.stdout.write(line + "\n")
        sys.stdout.flush()

def log(*args):
    """给自己看的消息：写到 stderr，会出现在 FullWidget 的 app.log。"""
    print(*args, file=sys.stderr, flush=True)

def slow(params):
    time.sleep(3)
    return "done"

METHODS = {
    "hello": lambda p: f"你好，{p['name']}",
    "add": lambda p: p["a"] + p["b"],
    "slow": slow,
}

def handle(req):
    try:
        fn = METHODS.get(req.get("method"))
        if fn is None:
            send({"id": req["id"], "error": f"没有方法 {req.get('method')}"})
            return
        send({"id": req["id"], "result": fn(req.get("params") or {})})
    except Exception as e:
        send({"id": req.get("id"), "error": f"{type(e).__name__}: {e}"})

def ticker():
    while True:
        time.sleep(5)
        send({"event": "tick", "data": {"time": time.strftime("%H:%M:%S")}})

log("started")
threading.Thread(target=ticker, daemon=True).start()
for line in sys.stdin:                      # 读到结尾：FullWidget 要我们结束
    if not line.strip():
        continue
    req = json.loads(line)
    # 每个请求一个线程：慢的 slow 不会卡住后面的请求
    threading.Thread(target=handle, args=(req,), daemon=True).start()
log("stopping")
```

要用第三方库时，在插件文件夹开终端运行 `python -m pip install 包名`；想和别的 Python 项目分开，就建一个虚拟环境（`python -m venv .venv`，再 `.venv\Scripts\pip install 包名`），`run` 写 `".venv\\Scripts\\python.exe main.py"`。

### Node.js

文件夹 `plugins\demo\`。要先装 [Node.js](https://nodejs.org/)。

`plugin.json`：

```json
{ "name": "示范（Node.js）", "run": "main.js" }
```

`main.js`：

```js
const readline = require("node:readline");

const send = (obj) => process.stdout.write(JSON.stringify(obj) + "\n");
const log = (...args) => console.error(...args);   // stderr → FullWidget 的 app.log

const methods = {
  hello: (p) => `你好，${p.name}`,
  add: (p) => p.a + p.b,
  slow: () => new Promise((r) => setTimeout(() => r("done"), 3000)),
};

async function handle(req) {
  const fn = methods[req.method];
  if (!fn) return send({ id: req.id, error: `没有方法 ${req.method}` });
  try {
    send({ id: req.id, result: await fn(req.params || {}) });
  } catch (e) {
    send({ id: req.id, error: String(e && e.message || e) });
  }
}

log("started");
const timer = setInterval(() => send({ event: "tick", data: { time: new Date().toTimeString().slice(0, 8) } }), 5000);

const rl = readline.createInterface({ input: process.stdin });
rl.on("line", (line) => { if (line.trim()) handle(JSON.parse(line)); });   // 不 await：请求可以同时处理
rl.on("close", () => { log("stopping"); clearInterval(timer); process.exit(0); });   // stdin 关了：结束
```

`console.log` 会写到 stdout，在插件里不要用它来调试，用 `console.error`。要用 npm 包，在插件文件夹运行 `npm install 包名`，`node_modules` 放在插件文件夹里就可以。

### PowerShell

不用另外安装，Windows 自带。文件夹 `plugins\demo\`。文件存成 **UTF-8 with BOM**（不然中文会乱码；记事本“另存为 → 编码：UTF-8 with BOM”）。

`plugin.json`：

```json
{ "name": "示范（PowerShell）", "run": "main.ps1" }
```

`main.ps1`：

```powershell
[Console]::OutputEncoding = New-Object Text.UTF8Encoding $false

function Send($obj) {
  [Console]::Out.WriteLine(($obj | ConvertTo-Json -Compress -Depth 10))
  [Console]::Out.Flush()
}
function Log($text) { [Console]::Error.WriteLine($text) }   # stderr → app.log

$methods = @{
  hello = { param($p) "你好，$($p.name)" }
  add   = { param($p) $p.a + $p.b }
  slow  = { param($p) Start-Sleep -Seconds 3; "done" }
}

function Answer($text) {
  $req = $null
  try {
    $req = $text | ConvertFrom-Json
    $m = $methods[$req.method]
    if (-not $m) { Send @{ id = $req.id; error = "没有方法 $($req.method)" }; return }
    Send @{ id = $req.id; result = (& $m $req.params) }
  } catch {
    Send @{ id = $(if ($req) { $req.id } else { $null }); error = $_.Exception.Message }
  }
}

Log "started"
# 用 OpenStandardInput 读：Windows PowerShell 5.1 的 [Console]::In 在等输入时会卡住整个程序
$reader = New-Object IO.StreamReader([Console]::OpenStandardInput(), (New-Object Text.UTF8Encoding $false))
$next = $reader.ReadLineAsync()
$lastTick = Get-Date
while ($true) {
  if (-not $next.Wait(500)) {
    if (((Get-Date) - $lastTick).TotalSeconds -ge 5) {
      $lastTick = Get-Date
      Send @{ event = "tick"; data = @{ time = (Get-Date -Format "HH:mm:ss") } }
    }
    continue
  }
  $text = $next.Result
  if ($null -eq $text) { break }          # stdin 关了：结束
  if ($text.Trim()) { Answer $text }
  $next = $reader.ReadLineAsync()
}
Log "stopping"
```

PowerShell 一次只做一件事：`slow` 的 3 秒里，其他请求和 tick 都要等。工作很慢的话，用 Python、Node.js 或 C# 会比较好；或用 `Start-Job` 自己调度。

### C#

适合要用 Windows API、或想做成一个 `.exe` 的情况。要先装 [.NET SDK](https://dotnet.microsoft.com/download)。

在任何地方创建项目（不要放在插件文件夹里，不然每次建置都会触发插件重新启动）：

```bat
dotnet new console -n DemoPlugin
cd DemoPlugin
```

`Program.cs`：

```csharp
using System.Text;
using System.Text.Json;
using System.Text.Json.Nodes;

Console.OutputEncoding = new UTF8Encoding(false);
Console.InputEncoding = new UTF8Encoding(false);
var stdout = Console.Out;
var gate = new object();

void Send(JsonObject obj)
{
    string line = obj.ToJsonString();                 // 一行，没有缩进
    lock (gate) { stdout.WriteLine(line); stdout.Flush(); }
}
void Log(string text) => Console.Error.WriteLine(text);   // stderr → app.log

async Task<JsonNode?> Run(string method, JsonNode? p) => method switch
{
    "hello" => $"你好，{(string?)p?["name"]}",
    "add" => (double)p!["a"]! + (double)p!["b"]!,
    "slow" => await Task.Delay(3000).ContinueWith(_ => (JsonNode?)"done"),
    _ => throw new InvalidOperationException($"没有方法 {method}"),
};

async Task Handle(string text)
{
    JsonNode? id = null;
    try
    {
        var req = JsonNode.Parse(text)!.AsObject();
        id = req["id"]?.DeepClone();
        var result = await Run((string)req["method"]!, req["params"]);
        Send(new JsonObject { ["id"] = id, ["result"] = result });
    }
    catch (Exception e)
    {
        Send(new JsonObject { ["id"] = id, ["error"] = e.Message });
    }
}

Log("started");
using var timer = new Timer(_ => Send(new JsonObject
{
    ["event"] = "tick",
    ["data"] = new JsonObject { ["time"] = DateTime.Now.ToString("HH:mm:ss") },
}), null, 5000, 5000);

while (Console.ReadLine() is string line)             // null：stdin 关了，结束
    if (line.Trim().Length > 0) _ = Task.Run(() => Handle(line));   // 每次都是新的 line，不会被下一行盖掉
Log("stopping");
```

建置成一个 `.exe`，放进插件文件夹：

```bat
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o "%AppData%\FullWidget\plugins\demo\bin"
```

`plugin.json`：

```json
{ "name": "示范（C#）", "run": "bin\\DemoPlugin.exe" }
```

`--self-contained false` 的 exe 很小，FullWidget 本身需要的 .NET 9 已经装好；如果你的电脑用的是 FullWidget 的“免安装完整版”，改成 `--self-contained true`。

## 调试

**先在终端里单独测试插件。** 在插件文件夹打开终端，把一行请求送进去，看它回什么：

```bat
echo {"id":1,"method":"hello","params":{"name":"test"}} | python main.py
```

```powershell
'{"id":1,"method":"hello","params":{"name":"test"}}' | node main.js
```

应该看到一行 `{"id":1,"result":"你好，test"}`。也可以直接运行 `python main.py`，自己贴 JSON 进去、按 Enter，看回答；按 Ctrl+Z 再 Enter（Windows）结束输入，插件应该自己退出。

**看日志。** `%LocalAppData%\FullWidget\logs\app.log` 里有：

- `Plugin demo: started (main.py), pid 1234`：启动了，用的是什么命令。
- `[plugin demo] …`：插件写到 stderr 的内容，包括 Python 的错误堆栈。
- `[plugin demo] wrote something that isn't a JSON line`：标准输出写了不是 JSON 的东西。
- `Plugin demo: exited on its own (exit code 1)`：插件自己结束了，往上找它的错误消息。
- `Plugin demo: could not start "…"`：命令错了，或 `python`、`node` 不在 PATH 里。

**看控制中心。** “设置 → 插件”每一行显示状态（运行中／没在运行／等你允许／一直停下来）、哪些组件在用，和最后一次的错误。运行中的插件可以“重新启动”或“停止”。

**看组件。** 在控制中心“设置”打开“开发者模式”，在组件上按 F12 打开开发者工具，`call` 失败的消息会出现在 Console。

## 安全和限制

- 插件用你的身份运行，能做你在这台电脑上能做的任何事。所以插件要在“设置 → 插件”里**允许**之后才会运行，允许时会列出它要运行的命令；`plugin.json` 改过要再允许一次。
- 只有你自己写的组件能用插件。安装包（.fwz）和组件市场的组件都不能用你的插件（[官方插件](#官方插件)除外）；手动复制进来的组件，要你在“我的组件”里允许。
- 插件不能放进安装包（.fwz），组件市场也不收用插件的组件。要分享，就把插件文件夹和组件文件夹一起给对方，请对方自己放好、自己允许。
- 别人叫你把某个文件夹放进 `plugins` 时，先看清楚它在做什么。

### 官方插件

组件市场有“官方插件”专栏，只放 FullWidget 自己做的插件，名称都是 `fullwidget.` 开头，源代码在[组件市场的 plugins 文件夹](https://github.com/hmgvibe/fullwidget-market/tree/main/plugins)公开。在控制中心“添加组件 → 在线 → 官方插件”安装，装好就是允许的。任何组件（包括市场上的）都可以用官方插件，例如 `"plugin:fullwidget.perf"`。

| 官方插件 | 提供 |
|---|---|
| `fullwidget.perf` 性能数据 | 每秒的事件 `stats`：显卡使用率、显存、温度、功耗、频率，和每个在绘制画面的软件的帧率。方法：`stats`、`info`、`enableFps`。见它的 [README](https://github.com/hmgvibe/fullwidget-market/tree/main/plugins/fullwidget.perf) |
| `fullwidget.files` 文件 | 用户用插件的窗口选了文件夹之后，列出里面的文件和图标，打开、在资源管理器显示、拖出去、把文件放进来、改名、新建文件夹、删到回收站，有变化时送出事件 `changed`。只能碰用户选的文件夹。见它的 [README](https://github.com/hmgvibe/fullwidget-market/tree/main/plugins/fullwidget.files) |

## 常见错误

组件里 `call` 失败时 `e.message` 的内容：

| 消息 | 原因和做法 |
|---|---|
| `no plugin "demo" (looked for …\plugin.json)` | 插件文件夹里没有 `demo\plugin.json`。检查文件夹名称和位置 |
| `plugin "demo": plugin.json: …` | plugin.json 格式错误，或少了 `run` |
| `plugin "demo" hasn't been allowed yet` | 去“设置 → 插件”按“允许” |
| `plugin "demo" could not start "…"` | `run` 的命令找不到：路径错了，或 Python／Node 没装、不在 PATH 里 |
| `plugin "demo" didn't answer "hello" within 30 s` | 插件没有回答：没 flush、`id` 写错、卡住了，或工作真的太慢（用 `{ timeout }` 等久一点） |
| `plugin "demo" stopped (exit code 1)` | 插件在回答前结束了，看 `app.log` 里它的错误 |
| `plugin "demo" kept stopping and was left stopped` | 3 分钟内崩溃 5 次。修好后在“设置 → 插件”按“重新启动” |
| `plugin "demo" was stopped` | 你在控制中心按了“停止”，或插件被重新启动 |
| `permission denied: add "plugin:demo" to permissions in widget.json` | `widget.json` 的 `permissions` 没写 `"plugin:demo"` |
| `permission "plugin:demo" is declared but the user has not allowed it yet` | 组件是手动复制进来的：在控制中心“我的组件 → 这个组件”允许它的权限 |
| `built-in widgets don't use "plugin:demo"` | FullWidget 内置的组件不能用插件，请用自己创建的组件 |
| 插件自己回的 `error` | 原样传过来，例如 `没有方法 foo` |

## 写完前检查

给自己（或 AI）对照：

- [ ] 插件文件夹名称就是组件里 `widget.plugin("…")` 用的名称，`widget.json` 有 `"plugin:名称"` 权限。
- [ ] `plugin.json` 有 `run`，而且在插件文件夹里运行这个命令能启动它。
- [ ] 标准输出只写 JSON 行，每行 flush；调试消息写 stderr。
- [ ] 每个请求都用同一个 `id` 回答一次，出错时回 `error` 而不是让程序崩溃。
- [ ] 慢的工作不会卡住其他请求（Python 用线程、Node 用 async、C# 用 Task）。
- [ ] 读到标准输入结尾就结束。
- [ ] 输入输出都是 UTF-8，中文不会乱码。
- [ ] 在终端用 `echo {...} | 命令` 测过，回答正确。
- [ ] 组件处理了 `call` 失败的情况，把 `e.message` 显示出来。
