# FullWidget 1.2.3 之後的更新：測試說明

測試版本：`1.2.3+e3bb7d4`（尚未發佈，版本號還是 1.2.3）；第七輪測試後修正 FW-11、FW-12，複測請用更新後的版本（見第 2、6 節）。
測試時請用獨立的資料夾，不要動到自己平常的設定：`FullWidget.exe --data-dir=<空資料夾>`。

---

## 1. 多螢幕：組件跟着自己的螢幕（Issue #1）

**改了什麼**：螢幕關掉或拔掉時，那個螢幕上的組件跟着一起隱藏（也停止更新），原本的位置不變；螢幕開回來後，組件在原位出現。打開「排列模式」時，這些組件會暫時出現在還在的螢幕上，方便把永久拔掉的螢幕上的組件拖過來（拖過的位置就成為新位置）。用快捷鍵叫出便籤、待辦清單時，即使它們在關掉的螢幕上，也會在還在的螢幕上出現。

**測試**
- 兩個螢幕，在副螢幕放幾個組件 → 關掉副螢幕：那些組件消失，主螢幕上的組件不受影響、不會多出組件。
- 再開回副螢幕（約 2 秒內）：組件在原來的位置出現。
- 副螢幕關著時重新啟動 FullWidget：那些組件仍然隱藏；開回副螢幕後出現在原位。
- 副螢幕關著時打開排列模式：那些組件出現在主螢幕；關掉排列模式又隱藏。把其中一個拖到新位置：它留在主螢幕，開回副螢幕後不再回去。
- `config.json` 裏組件的 `x`/`y`：螢幕關掉期間不應改變（除非手動拖過）。
- 本機只有一個螢幕，已用「放在沒有螢幕的位置」模擬過隱藏、排列模式、快捷鍵和拖動；螢幕真正開回來的那一步沒有實機測過。

## 2. 網速顯示不準（Issue #2）

**改了什麼**：只計算實體網卡；虛擬網卡（Hyper-V/WSL、VMware、VPN、Clash/mihomo 等代理的 TUN、藍牙）不算，避免同一份流量重複計算。每張網卡分開計算，新連上的網卡第一次讀數不算，避免突然出現巨大數字。

**第七輪後修正（FW-11）**：.NET 9 會把掛在網卡上的篩選驅動（QoS Packet Scheduler、WFP、Npcap、Native WiFi Filter 等）也列成網卡，各自回報和實體網卡完全相同的流量，所以上一版還是多算了約五倍。現在用 Windows 自己的標記（`GetIfTable2` 的 FilterInterface / HardwareInterface）排除篩選驅動和非硬體網卡，另外把同一實體位址、同樣計數的介面只算一次作為備援。「網路」組件的網卡清單也不再列出這些篩選驅動。
本機實測：下載 20 MB，組件增量 21,113,166 bytes，Windows WLAN 增量 21,113,213 bytes，比率 1.0000。

**測試**
- 用第七輪同樣的方法：記錄 `Get-NetAdapterStatistics -Name WLAN` 的 ReceivedBytes 和組件 `totalDown`，下載固定檔案後比較增量，比率應接近 1，不是 5。
- 「網路」組件的網卡清單：不應出現「…-QoS Packet Scheduler-0000」「…-WFP … Filter-0000」這類項目。
- 「網速」和「系統監控」組件的下載/上傳，和工作管理員或 TrafficMonitor 的數字應大致一致。
- 開著 VPN 或 Clash TUN 模式下載大檔案：不應出現兩倍、幾十倍的數字。
- 連上/斷開 Wi-Fi 或 VPN 的那一刻：不應跳出一個超大的瞬間值。

## 3. 控制中心空白（市場倉庫 Issue #1）

**改了什麼**：控制中心收集資料時，如果某個組件的資料有問題，只略過那個組件（記錄到日誌），不再整頁空白。資料 6 秒內沒到時，右側顯示「控制中心沒有載入成功」，附「再試一次」和「打開資料夾」按鈕，不再是一片空白。

**測試**
- 正常使用：從右鍵選單「設定…」、托盤圖示打開控制中心，各頁都正常。
- 多次關閉再打開控制中心：每次都有內容。
- （進階）手動把某個第三方組件的 `widget.json` 改壞再重新掃描：控制中心仍能打開，其他組件照常列出。

## 4. 匯率：可選中國銀行牌價

**改了什麼**：匯率組件設定新增「匯率來源」：國際市場價（原本的，每天更新）或「中國銀行外匯牌價」（一天更新多次，每 30 分鐘檢查）。選中國銀行時，再選用哪個價：中行折算價（預設）、現匯賣出價、現鈔賣出價、現匯買入價、現鈔買入價。

**測試**
- 來源選中國銀行、我的貨幣 CNY：數字和 https://www.boc.cn/sourcedb/whpj/ 一致（網頁是每 100 外幣的人民幣價格，組件顯示每 1 單位；日圓、韓元、新台幣等顯示每 100）。
- 切換五種價：數字跟着變。新台幣等只有現鈔價的貨幣，選現匯價時應改用現鈔價，不是空白。
- 我的貨幣改成 HKD 或 USD：用人民幣換算，數字合理。
- 底部顯示發佈時間（如「11/9 05:30 更新」）和「數據：中國銀行」，點擊打開中行牌價網頁。
- 切回國際市場價：恢復原本的數字和「ExchangeRate-API」。
- 輸入金額換算照常。

## 5. 快捷鍵（設定 → 快捷鍵）

**改了什麼**：兩個全域快捷鍵，在任何程式裏都能用。
- **顯示／隱藏全部組件**，預設 `Ctrl+Alt+W`。
- **叫出便籤**，預設 `Ctrl+Alt+N`：最近用過的便籤來到所有視窗最上面，游標直接在裏面可以打字；再按一次，或點別的視窗，便籤回到原本的層級，鍵盤交還給原來的視窗。桌面上沒有便籤時會新增一張。全部組件隱藏時也能叫出便籤，放回後再次隱藏。

**測試**
- 在瀏覽器或記事本裏按兩個快捷鍵，行為如上。
- 叫出便籤後直接打字：文字進到便籤；再按 `Ctrl+Alt+N`：繼續打字會回到原來的程式。
- 桌面層（最底層）的便籤叫出後要在最上面，連續叫出/放回多次都一樣。
- 設定頁點按鍵框錄新快捷鍵：只按字母會提示要加 Ctrl/Alt/Shift/Win；Esc 取消；Backspace 或「清除」關閉該快捷鍵。
- 兩個快捷鍵設成同一組：被拒絕並提示。
- 設成被其他程式占用的組合（例如 `Ctrl+Alt+Delete`）：顯示橘色「已被其他程式佔用」。
- 錄快捷鍵的時候，原本的快捷鍵不應觸發。
- 重新啟動後快捷鍵設定保留。

## 6. 媒體控制：歌詞

**改了什麼**：「媒體控制」組件顯示正在播放的歌詞，跟着播放進度走。用歌名、歌手和長度在網易雲音樂、QQ 音樂、酷狗的歌詞服務上查找，先查正在播放的那個軟件。歌名和歌手都要對上才採用（不會抓到翻唱），長度用來區分版本。開頭和結尾的作詞、作曲等資訊不顯示。找到的歌詞存在本機，下次不用再查。
- 預設大小：正在唱的那行取代歌手那行，歌手移到歌名後面（「晴天 · 周杰倫」）。
- 把卡片拉高或拉寬：變成多行歌詞，正在唱的那行在中間，其他行變淡，換行時平滑捲動；有翻譯的歌（如日文歌）每行下面顯示翻譯。
- 播放軟件沒有回報進度時，從歌曲開始計時，暫停時停住。
- 設定新增「顯示歌詞」「顯示歌詞翻譯」。

**第七輪後修正（FW-12）**：同歌名、同歌手但長度相差超過 2 秒時，視為另一個版本（Live、混音、剪輯版），會重新查歌詞，舊版本的歌詞立即撤下。長度相差 2 秒內視為同一版本，不重查。播放軟件一開始沒回報長度、稍後才回報時，先保留已找到的歌詞，用長度補查一次再換上。查詢結果帶回宿主查詢時用的長度；查詢期間歌曲或長度已經變了，舊結果直接丟棄，不會蓋掉新版本。`widget.media.lyrics()` 的回傳新增 `duration`（毫秒）。
本機受控測試（攔截查詢回應）：120 秒 → 240 秒重新查詢並顯示 240 秒版本；241 秒不重查；慢的舊回應晚到時被丟棄。

**測試**（以中國大陸的音樂軟件為主）
- 重做 FW-12 的受控步驟：同標題、同歌手，長度 120,000 → 240,000 ms，查詢次數應變成 2，畫面顯示 240,000 版本。注意：`widget.media` 是凍結的，換不掉 `widget.media.lyrics`，要在 `chrome.webview.postMessage` 攔截 `m: "media.lyrics"` 的請求，再用 `chrome.webview.dispatchEvent(new MessageEvent("message", { data: { id, r } }))` 回覆。
- 真實播放：在 QQ 音樂找同一首歌的錄音室版和 Live 版接連播放，兩者應各自顯示對應的歌詞（或 Live 版找不到時照常顯示歌手）。
- QQ 音樂、網易雲音樂、酷狗各播幾首：歌詞出現，和唱的同步（誤差約半秒內）。
- 切歌、暫停、繼續、拖動進度：歌詞跟着跳到正確的行。
- 翻唱/Live 版、純音樂、冷門歌：不應顯示別首歌的歌詞；找不到時照常顯示歌手。
- 日文或英文歌：卡片拉高後顯示翻譯；關掉「顯示歌詞翻譯」後不顯示。
- 關掉「顯示歌詞」：回到原本的樣子，也不再聯網查歌詞。
- 三套主題、三種大小（預設、拉寬拉高、直的）下都清楚好讀，沒有被裁切或重疊。
- 斷網時播放：不報錯，照常顯示歌手；恢復網路後換一首歌能找到歌詞。

**已確認**：QQ 音樂會回報播放進度，實測同步正確。網易雲音樂、酷狗的播放未在真機上測過（歌詞查找本身已測過）。

## 7. 軟件內更新（設定 → 關於）

**改了什麼**：FullWidget 可以自己更新。
- **檢查**：「設定 → 關於」按「檢查更新」時向 GitHub 查詢最新的正式版。「自動檢查更新」預設關閉；打開後，啟動一分鐘後檢查一次，之後每 12 小時一次。有新版本時，托盤彈出提示（每個版本只提示一次，點提示會打開設定）；托盤選單第二行多一項「更新到 x.y.z…」。- **更新**：按「更新到 vx.y.z」後下載和這份 FullWidget 同一種的檔案，顯示進度，可以取消：
  - 用安裝程式裝的（資料夾裏有 `unins000.exe`）：下載 setup.exe。
  - 自帶 .NET 的 zip（資料夾裏有 `hostfxr.dll`）：下載 `-full.zip`。
  - 其他：下載普通 zip。
- **驗證**：下載的檔案必須和 GitHub 標示的 SHA-256 一致；zip 裏 FullWidget.dll 的版本必須是發佈的版本號。目前正式版還沒有程式碼簽章；之後 release 流程設好 SignPath，正在執行的 FullWidget 有簽章時，新版也必須有同一個簽署者的有效簽章才會安裝。
- **安裝**：
  - 安裝版：靜默執行安裝程式（`/VERYSILENT /relaunch=1`），裝完自動重新打開。
  - zip 版：解壓後由新版自己替換檔案。新版有的檔案和資料夾整個換掉（舊版多出來、新版已移除的組件檔案會消失）；只有原資料夾才有的東西（便攜模式的 `data`、`portable` 標記）保留。替換前先把舊檔案移到隱藏的 `.update-old`，任何一步失敗就放回去，再重新打開舊版。新版打開後托盤提示「FullWidget 已更新到 x.y.z」，並清掉下載和 `.update-old`。
- **不會更新的情況**（改成顯示「到網站下載」）：
  - 程式所在的資料夾不能寫入。
  - 用 `FULLWIDGET_DEV_ROOT` 跑的開發副本。
  - 發佈裏沒有對應的檔案。
  - 驗證不通過。

**本機已測**（免安裝 zip 版，用本機的假 GitHub 回應）：
- 1.2.3 → 1.2.4 約 1 秒完成替換並自動重新打開。新版不帶的檔案被刪除，資料夾裏使用者自己的檔案保留，暫存都清乾淨了。
- SHA-256 不符：拒絕安裝，半截檔案刪除，舊版照常運行。
- SHA-256 正確但 zip 裏是別的版本：拒絕安裝。
- 托盤選單出現「更新到 1.2.5…」。

**沒測過**：安裝版（這台電腦沒有 Inno Setup，靜默安裝後重新打開要等真的發佈才能測）；真實 GitHub 下載速度（中國大陸網路下 GitHub 下載可能很慢或失敗，失敗時顯示「下載中斷了」可再試）。

**測試**
- 用 `FULLWIDGET_UPDATE_FEED` 環境變數指向一個假的 release JSON（格式同 `https://api.github.com/repos/hmgvibe/FullWidget/releases/latest`，至少要有 `tag_name`、`html_url`、`assets[].name/size/digest/browser_download_url`；只接受 https，或 127.0.0.1 上的 http）。版本號用 `dotnet publish -p:Version=1.2.9` 打包一個假的新版。
- 免安裝版：放一份舊版到可寫的資料夾，`--data-dir` 指向空資料夾，檢查更新 → 更新 → 確認自動重開、`FullWidget.dll` 版本、組件和設定都還在。
- 便攜模式（資料夾裏有 `portable` 檔案）：更新後 `data` 資料夾完整保留。
- 改壞 digest、把 zip 換成別的版本、下載途中按取消、斷網時檢查：都不應安裝，舊版照常運行，顯示對應的提示和按鈕。
- 放在不能寫入的資料夾（例如 `C:\Program Files\`）：顯示「到網站下載」。
- 新的資料夾（預設設定）啟動：「自動檢查更新」是關的，一分鐘後不應連 GitHub；打開後一分鐘內會檢查。關掉後重開也不應連（看 `local\logs\app.log` 沒有 `Update:` 記錄）。
- 等正式發佈 1.2.4 之後：用安裝版的 1.2.4 測更新到下一版。

## 8. 記憶體

**改了什麼**：
- 啟動完成約 30 秒後，把 FullWidget 和 WebView2 各進程啟動時用過、之後不再用的記憶體交還給 Windows。之後只在控制中心或文件視窗關閉、增刪組件時，等 30 秒再交還一次；不定時重複。
- 右鍵選單的網頁不再在啟動時預先建好：第一次用到時才建立（約 0.3 秒；滑鼠移到托盤圖示上時會先準備），閒置 3 分鐘後釋放。

**本機實測**（任務管理器「記憶體」的算法＝私有工作集；FullWidget.exe 加上它的所有 msedgewebview2.exe，啟動 4 分鐘後）：

| 組件數 | 改之前 | 改之後 |
|---|---|---|
| 3（預設） | 149 MB | 78 MB |
| 13 | 240 MB | 120 MB |
| 38 | 454 MB | 245 MB |

提交記憶體（Commit）不變；交還的是實體記憶體。13 個組件連續觀察 20 分鐘，穩定在 125 MB 左右，不會漲回去。試過沒有用的：多種瀏覽器參數、關閉渲染無障礙、.NET GC 設定、WebView2 低記憶體目標（都在 ±5 MB 內）。

**測試**
- 注意：任務管理器「進程」頁上的 FullWidget 只是主程式；組件跑在另外列出的「Microsoft Edge WebView2」進程裏。要看合計，在「詳細資料」頁把 FullWidget.exe 和命令列帶 `FullWidget\WebView2` 的 msedgewebview2.exe 加起來。
- 啟動 1 分鐘後和 10 分鐘後各看一次合計；組件照常更新（系統監控的數字在變、時鐘在走、動畫順暢）。
- 右鍵組件或托盤：選單正常出現；閒置 3 分鐘後再打開，稍慢一點（約 0.3 秒）但正常。
